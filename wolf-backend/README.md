# Wolf private alpha backend

This Worker is independent of GitHub Pages. The existing tracker and scanner are not changed. The Wolf UI remains in draft PR #1; do not merge it until authentication, citations and end-to-end checks are connected.

## Cloudflare Git integration

- Project name: `wolf-ai-backend`
- Production branch: `main`
- Advanced settings / Path: `wolf-backend`
- Build command: leave empty
- Deploy command: `npx wrangler deploy`
- Disable preview builds for this private alpha.
- Leave build variables empty. The API token generated by Cloudflare is its deployment credential, NOT the OpenAI API key.

Once deployed, add **runtime Secrets** in the Worker's Settings / Variables and Secrets:

- `OPENAI_API_KEY`: the OpenAI key (never commit or send through chat).
- `WOLF_TEST_TOKEN`: a separate random password of at least 32 characters, generated and saved using a password manager. This is the private tester access code, not the OpenAI key.

Keep `WOLF_ENABLED` set to `false` until the client is connected. To enable testing, change that variable to `true` and deploy. Configuration in wrangler.jsonc is authoritative on subsequent Git deployments; change its non-secret enabled flag intentionally if testing should remain enabled after future deployments.

## HTTP contract

`GET /health` returns the service status without making a paid call.

`POST /ask`: `Authorization: Bearer <private test access code>` and `Content-Type: application/json`. Body: `{question, context, untrackedNotes, messages}`. Success: `{answer, sources:[{title,url}], usage}`. Use textContent for answers and visible clickable HTTPS source links. Do not expose an OpenAI key to the browser. Keep the temporary tester code only in memory and request it when needed. The current draft client must be updated to this bearer-token contract (remove credentials:include) and render returned sources before public use.

Requests are rejected before OpenAI if disabled, missing secrets, unauthenticated, invalid, too large, or out of quota. A persistent atomic global limiter permits 3/minute, 20/UTC day and 100 lifetime attempts across all testers. Failed calls consume an attempt. Changing or deleting the limiter object resets counts; do not do that casually. These are request caps, not an exact dollar budget. Context, retrieved search content, reasoning and search tools all affect actual cost. Inspect OpenAI usage before raising limits.

Uses GPT-6.1 Sol, low reasoning, at most 2 search calls and 2,000 output/reasoning tokens; bounded 16 KB incoming JSON and no paid auto-retries. Searches Wizards and Scryfall. Missing boards are unknown; no game writes. The test token is a temporary single-owner gate, not a paid-membership system. Public launch requires individual authentication, entitlements and per-user usage accounting.

## Validation

`npm test` exercises unauthorized/disabled requests, body bounds, source handling, upstream errors and persistent request limits with mocks. It does not verify Cloudflare deployment, account model availability, actual AI answer quality or iPhone integration. Those require the user's configured secrets and a private live test.
